# #151 백엔드 검증 코드를 zod 4 문법으로 옮기기

- 이슈: [#151](https://github.com/sirloinbh/study-log/issues/151)
- 브랜치: `chore/151-zod4-syntax`

## 목적

중앙 `sirloinbh/project-standards#386`의 1단계다. 중앙이 `zod`를 4.6.7로 올릴 때 이 앱이 깨지지 않도록 코드를 먼저 옮긴다. 보안 권고 GHSA-mrhx-c7xc-m3w5의 Dependabot 알림은 그 동기화로 닫힌다. 이 PR만으로는 닫히지 않는다.

## 변경 — 2026-11-01

- `backend/src`의 zod 파일 11개가 `zod/v4`에서 불러온다. 설치된 3.25.76에 이 경로가 들어 있어 패키지 버전과 잠금 파일은 바꾸지 않았다.
- `required_error`, `invalid_type_error`, `errorMap`을 `error`로 옮겼다. 두 메시지가 다른 곳은 `backend/src/validation.ts`의 `missingOrInvalid`를 쓴다.
- 문자열 길이 검사 `.min()`, `.max()`를 `.refine()`으로 바꿨다. zod 4의 길이 검사는 타입 검사에 실패한 배열에도 돌아 메시지가 덧붙고, 4.6.7의 `.max()`는 UTF-16 단위가 아니라 코드 포인트로 센다.
- 배열의 `.min(1)`도 `.refine()`으로 바꿨다. 배열의 `.max()`는 그대로 두고 맨 앞에 놓았다. 4.6.7은 `.max()` 앞에 다른 검사가 없을 때만 원소를 읽기 전에 거절한다.
- 반복된 쿼리 값이 zod 기본 영어 문구로 나가던 `textbookId`, `contentId`에 한국어 메시지를 넣었다.
- `backend/test/zod4-validation.test.ts`: 기본값, 없는 값과 잘못된 타입의 메시지, 배열 길이 제한을 확인한다.

## 구현 판단

- `.default()`는 모두 스키마 끝에 있고, `.partial()`과 `.default().optional()`은 없다. 뒤에 `.transform()`이 붙은 기본값도 없다. 기본값을 바꾼 곳은 없다.
- `z.record`는 이 앱에 없다. `{"constructor":null}`처럼 3.25.76의 `z.record`에서 문제가 되는 입력은 해당하지 않으며, 비교에서도 500이 나지 않았다.
- `.merge()`, `ZodError.errors`, `z.string().email()` 형태도 쓰지 않는다.
- `.int()`는 그대로 뒀다. 아래 1, 2번 차이를 없애려면 정수 검사를 모두 `.refine()`으로 바꿔야 하는데, 잘못된 요청의 중복 문구만 달라지므로 바꾸지 않았다.

## 바뀌는 응답

같은 요청 18,148개를 전환 전(zod 3), 3.25.76의 `zod/v4`, 4.6.7의 `zod/v4`에 보내 비교했다. DB는 호출 값을 기록하는 가짜 풀을 썼다.

| 비교              | 상태 코드가 다름 | DB에 넘긴 값이 다름 | 오류 문구가 다름 |
| ----------------- | ---------------: | ------------------: | ---------------: |
| 전환 전 → 3.25.76 |                0 |                   0 |            2,055 |
| 3.25.76 → 4.6.7   |                0 |                   0 |              168 |
| 전환 전 → 4.6.7   |                0 |                   0 |            1,895 |

성공 요청 840개는 상태 코드와 DB 값이 모두 같았다. 문구가 다른 요청은 모두 원래도 400이었고, 대부분 잘못된 필드를 둘 이상 섞은 비교용 입력이다. 전환 전과 비교한 차이는 다음과 같다.

|   # | 입력 예                                                      | 전환 전                                            | 전환 후                                                                                                                |
| --: | ------------------------------------------------------------ | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
|   1 | `limit=0.5`, `understanding: 0.5`                            | 정수 문구와 범위 문구 둘 다(같은 문구면 두 번)     | 정수 문구만                                                                                                            |
|   2 | `limit=1e20`, `textbookId: 1e20`                             | 범위 문구만                                        | 정수 문구와 범위 문구 둘 다                                                                                            |
|   3 | `limit=1e400`(Infinity)                                      | 정수 문구와 범위 문구 둘 다                        | 타입 문구(정수 문구와 같은 글)만                                                                                       |
|   4 | `contentId: 0.5`와 `textbookId: null`, `ids: [0.5, 0.5]`     | 필드 문구와 교차 검사 문구                         | 필드 문구만                                                                                                            |
|   5 | `from=abc&to=2026-01-15`                                     | 형식 문구와 `시작일은 종료일보다 늦을 수 없습니다` | 3.25.76: 형식 문구만. 4.6.7: 전환 전과 같음                                                                            |
|   6 | `ids`, `entries`에 제한보다 긴 문자열이나 `length`가 큰 객체 | 타입 문구만                                        | 타입 문구와 개수 제한 문구                                                                                             |
|   7 | `textbookId=1&textbookId=2`, `contentId=1&contentId=2`       | `Expected string, received array`                  | `교재 ID가 올바르지 않습니다`, `목차 ID가 올바르지 않습니다`                                                           |
|   8 | 제한을 넘은 배열                                             | 개수 제한 문구, 원소 또는 교차 검사 문구           | 3.25.76: 원소가 모두 유효하면 전과 같고, 잘못된 원소가 있으면 원소 문구들 뒤에 개수 제한 문구. 4.6.7: 개수 제한 문구만 |

전환 전과의 차이는 종류별로 나눠 모두 위 표에 넣었다. 7번만 영어에서 한국어로 바꾼 의도한 변경이고, 나머지는 zod 4의 동작 차이를 그대로 둔 것이다. `constructor`, `__proto__` 키를 넣은 요청 265개는 세 버전의 상태 코드와 문구가 모두 같았다.

## 검증

- `npm run check`: 통과. 백엔드 292개 중 265개 통과, 27개 건너뜀, 프론트엔드 125개 중 123개 통과, 2개 건너뜀, 스킬 4개 통과. `TEST_DATABASE_URL`을 비워 실행해 DB 통합 테스트는 건너뛰었고, PR CI로 확인한다.
- 앞선 실행 한 번에서 `frontend/src/stats-review.test.tsx`가 5초 제한을 넘겨 실패했다. 프론트엔드는 바꾸지 않았고, 다시 실행한 `npm run check`에서는 통과했다.
- `npm run standards:check`: 통과.
- 4.6.7은 `node_modules/knip/node_modules/zod` 사본으로 HTTP 응답만 비교했다. 테스트 전체와 타입 검사를 4.6.7로 돌리지는 못했고, 중앙 동기화 PR의 CI로 확인한다.
