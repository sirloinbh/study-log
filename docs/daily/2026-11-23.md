## Migration-number clashes and the new rule

Lanes added migrations in parallel and the numbers collided twice after the lanes had merged `origin/main`, so a duplicate number reached `main` and broke it twice (as the coordinator counted them). The renumbering commits show:

- the weekly goals migration (#361) and the keyword cards migration (#359) both took 028; PR #388 renumbered weekly goals to 029;
- the exercise review migration (#358) was renumbered several times (026, 027, 028) and ended as 030 in PR #380.

Migration 027 is unused. Now `database/migrations` runs 001 to 032. The rule added to the lane file: right before the final push, and again right before `pr merge`, run `git fetch origin && git ls-tree --name-only origin/main database/migrations/` and check that your number is still free; renumber and rerun the check if it is not. Also run `node .standards/check.mjs` before each push, because `npm run check` does not run the standards check.
